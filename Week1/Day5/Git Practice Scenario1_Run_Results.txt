Bonus questions - concise answers
==============================================================================
1. git fetch downloads objects and updates remote-tracking refs without changing the current branch; git pull fetches and then integrates the selected remote branch.
2. Use git revert on shared history because it adds an inverse commit without rewriting commits other people may already have.
3. Rebase rewrites commit IDs; rebasing shared commits can invalidate collaborators' branches and cause duplicate or conflicting histories.
4. git reset --hard moves HEAD and resets the index and working tree, discarding uncommitted changes; git reflog records prior HEAD positions and can identify a commit to restore.
5. git bisect performs a binary search through commit history using known good and bad points to find the first commit that introduced a bug.
